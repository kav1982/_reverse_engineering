奥爆术 · Spell1008

Missile 主动法术 · ID 10081–10083 · 枪口原地瞬爆 · 判定分 R/2 与 R 两段 · 每个敌人只挨一次 · 2/3 级击杀免费连锁

1. 是什么

在法杖射击点原地瞬发一个圆形爆炸（不是鼠标位置，也没有任何飞行段）。判定分两段：生成瞬间先用 半半径 R/2 打一次，0.3 秒后再用 全半径 R 补一次；命中去重表保证同一敌人只挨一次伤害。实体在 0.6 秒后销毁。

2/3 级（int1=1）带击杀连锁：被它打死的单位会在尸体处免费再生成一发同参数奥爆术，不扣蓝、没有递归深度上限。

  • ECS 主路径：Spell1008ArcaneExplosionSystem + Spell1008Job（视觉与伤害排程）+ Spell1008TakeDamageJob（执行伤害）
  • 坠落形态另走 Spell1008OnGroundJob / Spell1008FallEffectJob / Spell1008FallJob
  • 击杀连锁不在 1008 文件里，挂在通用的 SpellTakeDamageResultSystem 上
  • Mono Spell1008ArcaneExplosion 为残留轨，只在 float1 一处作为对照出现

短评文案「施法处瞬间爆发的范围法术」准确但不完整——实际有 0.3 秒的第二段判定。

3. 关键：两个被硬覆盖的字段

这是理解奥爆术全部符文交互的钥匙。SipToSSP（发射包组装）的最后一步调用处理器：

SpellSpawnParamsProcessor.cs L44–48处理器
_processors.Add(SpellAbilityType.ArcaneExplosion, delegate(... ref SpellSpawnParams ssp)
{
    ssp.MovementComponentData.Speed = 0f;
    ssp.ConfigComponentData.Duration = new AttributeValue(0.6f);
});

第二行不是「修改 Base」，而是整个赋值一个新结构体。而 AttributeValue(float) 的第一句就是 this = default(AttributeValue)：

AttributeValue.cs L16–27构造函数清空全部修正位
public AttributeValue(float baseValue = 0f)
{
    this = default(AttributeValue);   // AddBase / AddRatio / Extra 全部归零
    Base = baseValue;
    MulRatio = 1f;
}
public readonly float Calculate()
    => (Base + AddBase) * (1f + AddRatio) * MulRatio + Extra;

就在 3 行代码之前，SipToSSP 才刚把时长强化的 sip.extraDuration、节能模式的 sip.finalDurationRatio 攒进 Duration 的 AddBase 与 MulRatio（L274–279）——全部被丢弃。

净效果 Duration.Calculate() ≡ 0.6 任何符文都改不动 Speed ≡ 0 非坠落形态永远不移动

唯一的例外是坠落形态：SpellInitialFallData 在 L513 就已经把含加速器加成的速度落袋到 CurrentFallSpeed / OriginalSpellHorizontalSpeed，而处理器在 L517 只归零 Speed 一个字段。这是执行顺序上的巧合，不是专门设计。

5. 判定始终领先于表现

爆炸球的视觉半径曲线（Spell1008Job L157，注意 num6 取的是 DurationTimer 的原始秒数而非归一化进度）：

R_vis(t) = 1.2 · R · (2t − t²)
t=0 · 判定 0.50R · 视觉 ≈0
t=0.3 · 判定 1.00R · 视觉 0.61R
t=0.6 · 销毁 · 视觉 1.008R
时刻视觉半径判定半径差距
t = 0（第一段）≈ 00.50 R画面上什么都还没有，伤害已结算
t = 0.3（第二段）0.612 R1.00 R判定领先 63%
t = 0.6（终点）1.008 R—视觉刚好追平判定半径

整个生命周期里判定都跑在表现前面。玩家看到火球边缘刚扩到六成，站在最外沿的敌人就已经结算完了。这是奥爆术手感「比看起来大」的根因。1.2 这个系数显然是照着 0.6 秒寿命调的：1.2 × (1.2 − 0.36) = 1.008。

被 0.6 秒救下来的隐患：Spell1008Job L155 每帧把 DurationTimer 钳到 [0,1]，而销毁条件是 DurationTimer ≥ Duration.Calculate()。若 Duration 能被抬过 1 秒，计时器将永远追不上寿命，爆炸永不销毁。没出事纯粹是因为 Duration 恒为 0.6——两个 bug 互相抵消。

public SpellSpawnParams BuildArcaneExplosion(float3 spawnPosition, float randomAngle)
{
    SpellSpawnParams ssp = Params;
    ClearTriggerInfoAndSubGroup(ref ssp);   // 只清触发器，不碰任何数值
    ssp.SpawnPosition = spawnPosition;      // ← 死者所在处
    ssp.MovementComponentData.AroundAngle = randomAngle;
    ssp.MovementComponentData.FallTargetPosition = spawnPosition;
    return ssp;
}

完整继承

  • Damage（含法杖/符文全部加成）
  • Radius（含范围增强）
  • CriticalChance、元素、配色
  • Int1 → 衍生体自己也能再连锁
  • IsFallSpell → 连锁体也是坠落形态

不消耗

  • 不走 ShootSpellUtils，不扣蓝
  • 不占施法次数、不吃冷却
  • 没有连锁计数 / 递归深度字段
  • 天然收敛靠 isTriggerDeadEvent（过滤尸体）与敌人总量

三个触发条件缺一不可：Int1 != 0（1 级没有连锁）、isTargetDead、isTriggerDeadEvent。在高密度杂兵房里，一发 2/3 级奥爆术可以引发全屏连爆——这是它作为「普通」稀有度却强度偏高的数值根源。

float1 在 ECS 路径上没有实现

机制文案 7110082 写着「生成一次 float1 倍半径 的奥爆术」，Lv2 的 float1 = 0.7。但 BuildArcaneExplosion 没有任何 Radius / Float1 运算，全部 20 个 Spell1008*.cs 里 Float1 也不出现在任何 gameplay 分支。只有 Mono 残留轨里有：

Spell1008ArcaneExplosion.cs L209Mono 残留轨（玩家路径不经过）
spellInitialParameter.finalSizeRatio *= base.spellCfg.float1;
判定 迁移到 ECS 时漏掉的字段。当前 2 级奥爆术的连锁爆炸半径与主爆炸等大，不是 0.7 倍。 Lv3 的 float1 = 1.0 恰好等于「不缩放」，所以 3 级看不出差异——这也是它一直没被发现的原因。 对玩家而言这是隐藏的正收益。

齐射 vs 多重施法：一个叠伤，一个铺开

两者机制看起来相似，结果完全相反。齐射抬 shootCount，而发射包组装的双重循环里所有 InShootCountIndex 共享同一个 CreatePosition：

ShootSpellUtils.cs L782–795齐射：位置不变
for (int inShootCountIndex = 0; inShootCountIndex < config.shootCount; inShootCountIndex++)
    for (int inMultiShootIndex = 0; inMultiShootIndex < multiShootCount; inMultiShootIndex++)
        yield return new SpellShootInfo { ..., CreatePosition = position, ... };

齐射的散射只作用于 Direction，而 Speed = 0 让方向完全失效 → N 发精确重叠在同一点。每发有独立的 SpellEffectEntity，也就有独立的去重表，各自完整结算一次。

ShootSpellUtils.cs L684–692多重施法：横向平移
Vector3 dir = Tool2D.GetDir(lookDirection, 90f);   // 朝向的垂直方向
float num = (e.MultiShootCount - 1) * e.MultiShootGap * -0.5f
          + e.MultiShootGap * e.InMultiShootIndex;
return e.CreatePosition + num * dir;

齐射 = 无代价 ×N

  • N 发完全重叠于一点
  • 对单个敌人也是 N 倍伤害
  • 覆盖面积不变
  • 散射惩罚在此完全不存在
  • 蓝耗次线性（Pow 折扣）→ 收益超线性
  • 奥爆术的第一优先级符文

多重施法 = 横向铺开

  • N 发以 gap 为间距并列排开
  • 对单个敌人只有 1 倍（除非站在重叠区）
  • 覆盖面积近似 N 倍
  • 适合清成排杂兵

为什么一整类符文对它空转

依赖位移的

  • 反弹（不撞墙）
  • 自动导航 / 公转 / 寻踪
  • 加速器（非坠落）
  • 根因：Speed ≡ 0

依赖寿命的

  • 时长强化（100% 废槽）
  • 节能模式的时长档
  • 公转的 extraDuration
  • 根因：Duration ≡ 0.6

依赖碰撞的

  • 穿透（CostPenetrate: false）
  • 折射（非坠落无法触发，只剩伤害惩罚 = 负收益）
  • 根因：伤害走范围查询而非碰撞体

悬停：只吃新进场的敌人

HoverDuration 是唯一能改变奥爆术时序的外部输入（处理器只覆盖 Duration，不碰它）。悬停期每 0.4 秒重新入队一次全半径伤害，但去重表同样不清空。

实际语义：把一次性爆炸变成持续 HoverDuration 秒的滞留门禁区域。 · 打站桩目标 → 零收益（已挨过一次，之后永远跳过） · 守路口 / 卡门 / 持续刷怪 → 收益显著，每 0.4s 收一次新进场的敌人

视觉上悬停期间缩放块被整体跳过，爆炸球冻结在 t=0.45 对应的 0.837R 尺寸，直到悬停剩余不足 0.15 秒才补完动画并淡出。

8. 坠落形态

Spell1008ArcaneExplosionSystem.cs L541–544坠落参数改写
movement.OriginalSpellHorizontalSpeed += 8f;          // 在含加速器加成的值上再加
movement.Gravity = 20f;
movement.CurrentFallSpeed = OriginalSpellHorizontalSpeed * (IsSplitSpell ? -1 : 1);
movement.Speed = CurrentFallSpeed / math.tan(1.3089969f) * (IsSplitSpell ? -1 : 1);
//                                          ↑ 1.3089969 rad = 75°，tan ≈ 3.732

抛射角固定 75°，水平分量约为垂直分量的 26.8%——一条又高又陡的抛物线。这里重新给 Speed 赋值，绕过了处理器的归零，这就是坠落形态能动起来的原因。

  • 落地先判折射，后爆炸：Spell1008OnGroundJob 的范围查询不造成伤害，只喂给 TryRefractOrReboundWhenFall 判定。参数 hitUnitInThisDamage 是硬编码的 true——落点周围一个敌人都没有，折射也照常消耗并弹起。
  • 地面爆炸是独立实体：实例化 1008_Explosion_{颜色} 预制体并挂 Spell1008FallData，跑和非坠落一模一样的 R/2 → R 两段曲线，但 0.6f / 0.3f 在这里是写死的字面量，不再读 Duration。
  • 每个落点有独立去重表（EffectEntity 是地面爆炸实体自己）→ 同一个敌人会被多个落点分别命中。这是「折射 × 坠落 × 奥爆术」能打出多段伤害的机制根源。
  • 销毁握手：Spell1008FallJob 等所有地面爆炸 FinishDamageApply 后才置 SpellDestroyTag，避免伤害 buffer 丢失。

坠落符文还有个容易忽略的数值加成：sip.fallExplosionRadius 以加法形式进入 (Base + FallRadius) × (1 + AddRatio)，先加后乘，所以「坠落 + 范围增强」是乘法叠加，一起配收益超过各自单配之和。

10. 构筑摘要

强搭配（按优先级）

  • 齐射 3001 — 无代价伤害 ×N，完全重叠
  • 范围增强 3107 — 面积按平方增长，同时放大两段判定；单张符文的半径增幅很可能超过两级升级的总和
  • 伤害强化 3102 — 被击杀连锁完整继承
  • 精准施法 3105 — 只吃暴击那一半，但基数是 25% 高起点
  • 多重施法 3002 — 横向铺开，清成排杂兵

废槽位 / 负收益

  • 穿透 3006 — 连数字都不动
  • 时长强化 3103 — 100% 无收益
  • 反弹 / 自动导航 / 公转 / 寻踪 — 全依赖位移
  • 折射 3121 — 非坠落形态纯负收益（只剩伤害惩罚）
反直觉点速记 · 每个敌人对每发奥爆术只挨一次伤害 → 元素只挂一层，堆叠流不适用 · 悬停对已命中目标零收益，只拦新进场的敌人 · 1 级没有击杀连锁（int1=0），1→2 级是质变不是量变 · 2 级连锁半径没有按文案缩到 0.7 倍，实际与主爆炸等大 · 爆炸中心固定在法杖枪口，不是鼠标 → 只能贴脸炸，没有射程
