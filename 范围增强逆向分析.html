范围增强（Spell3107 / EnhanceRadiusRatio）逆向分析

范围：仅玩家强化符文「范围增强」（abilityType = 3107，配置 ID 31071–31073）。重点是加算怎么进半径，以及谁真正乘到这个半径。

不展开遗物/诅咒逐条来源，也不穷尽每个 abilityType 的 Job。

方法：SpellConfig.json + 反编译 Assembly-CSharp 交叉验证。未标注「推测」的结论均有代码/数据直接证据。

玩家施法主路径是 ECS。Mono SpellBase 叠加上限与 ECS 一致，分裂对坠落附加圈的处理不同，文末单独对照。

配套：总览见《魔法工艺法术系统逆向报告.md》，原始数值见《法术数值总表.md》，加算容器与槽位解析骨架见《伤害强化逆向分析.md》，子弹半径再 ×0.8 见《分裂逆向分析.md》。

2. 数值与叠加

2.1 配置表

IDLevelfloat1 加算半径%售价可合成

规律：float1 每级 ×2；售价每级 ×3。其余 int/float 全 0，不用。无耗蓝倍率。

2.2 字段语义

字段语义运行时是否被读置信度
float1加算半径百分比；AddRatio(float1 / 100)是高
float2 / float3 / int1–3配置为 0ECS 未读高
haveEffecforMissileSpell自动填槽：不是「只给召唤」仅自动填槽高
haveEffecforSummonSpell表上是 falseGetSpellEffectRadius 不读高

没有 Spell3107*System / Authoring。它不是行为组件，只被 GetSpellEffectRadius 读 abilityType 后改一个比率。

2.3 加算，不是连乘

两张 Lv1 是 +60%（×1.60），不是 1.3 × 1.3 = 1.69。

public RatioValue GetSpellEffectRadius()
{
    RatioValue ratioValue = new RatioValue(Spell.GetFinalConfig().radius);
    // ...
        case SpellAbilityType.EnhanceRadiusRatio:
            ratioValue.AddRatio(finalConfig.float1 / 100f);
            break;
        case SpellAbilityType.RadiuRatioDown:
            ratioValue.MulRatio(finalConfig.float1 / 100f);
            break;
}

switch 里没有「已处理过同类型就跳过」。同类型出现几次加几次。无上限、无「只取最高级」。

等级只改加数：1×Lv2 = 2×Lv1 = +60%，1×Lv3 = 4×Lv1 = +120%。合成省槽，不提高单点效率。

2.4 RatioValue 与 ECS 半径怎么对上

RatioValue.AddRatio 把内部 addRatio（初值 1）加上去；MulRatio 连乘 mulRatio（初值 1）。映射到实体时：

sip.extraSizeRatio += CurrentAddRatioStartZero    // addRatio - 1，即 Σ(float1/100)
sip.finalSizeRatio *= CurrentMulRatio             // 目前只有聚爆会改

Radius.AddRatio   = sip.extraSizeRatio
Radius.MulRatio   = GetSpellDecreaseRadiuSpeedInfo().radiusRatio
Radius.FallRadius = sip.fallExplosionRadius

Calculate() = (Base + FallRadius) * (1 + AddRatio) * MulRatio + Extra

SipToSSP 的 MulRatio 直接取聚爆的 radiusRatio，不读 sip.finalSizeRatio。当前只有聚爆写乘算，两边数值相同；分裂缩小半径不走这个字段。

2.5 同加算池：遗物 / 诅咒 / 法杖

3. 谁吃得到这张卡

3.1 只强化自己右边、同一段

SpellGroupParser 从左到右扫。遇到 Enhance 推进累积列表，消耗后不清空。主槽和后槽分别 Parse，互不串。

范奥爆弹→ 两张都吃
奥爆范弹→ 只有弹吃
奥爆弹范→ 都吃不到
范A奥爆范B弹→ 奥爆吃 A；弹吃 A+B

主槽最左的一张会强化本段之后所有主动/召唤。主槽加不到后槽。

3.2 haveEffecforSummonSpell=false 拦不住手动

GetSpellEffectRadius 不读两个 haveEffecfor*。手动插在召唤左侧，召唤物的爆炸 / 撞击 / 探测圈仍会变大。自动填槽的真正限制是「主法术表半径 > 0」和避让表。

3.3 魔能升阶抬的是这张卡的 float1

EnhanceList 取 GetFinalConfig()。魔能升阶把 31071 抬成 31072 / 31073。叠加规则不变，变的是送进 AddRatio 的百分比。

4. 谁真正乘到这个半径

运行时半径：

最终半径 = (表 radius + 坠落附加圈) × (1 + Σ范围增强 + 遗物/诅咒 + 法杖) × 聚爆乘算 + Extra

谁调用 Radius.Calculate() / CalculateIgnoreFall()，或手写等价倍率，谁就吃到。

硬编码圈（部分召唤自爆 / 撞击 / 探测）吃基数写死，再乘 (1+AddRatio)*MulRatio表 radius=0 也能变大
公转半径基本不吃AroundRadius 来自公转 float3，烘焙时不乘AI 距离估算会乘；个别法术用半径比做偏移
弹体碰撞盒不自动吃预制体碰撞体，不读 Calculate()除非该法术把 Scale 设成 Calculate()

4.2 分裂：继承加算，再缩底数

ToSplit 整包复制快照，不改 AddRatio / MulRatio / FallRadius，只做 Radius.Base *= 0.8、Radius.Extra *= 0.8。

子弹拿到发射时的满额加算。表半径先 ×0.8 再套同一套倍率，效果上等价于「范围增强也再 ×0.8」。

坠落附加圈不乘 0.8。 FallRadius 原样留下，再被 (1+AddRatio)*MulRatio 放大。[坠落][范][分裂][陨石] 的子弹：表半径缩小，坠落附加圈仍按母弹满额吃范围增强。

4.3 聚爆：乘算，并且转伤吃加算后的米

聚爆（3113）是半径的乘算层：当前 float1=50、float2=100，即半径 ×50%，少掉的米按 100% 转伤害。

转伤 = finalRadius / decreaseRatio × (1 - decreaseRatio) × convertRatio

finalRadius 已经含范围增强。圈做大后，聚爆「少掉的米」也变多，转伤更高——这是聚爆吃加算层，不是范围增强自己转伤。

开火烘焙算转伤时，只用槽位里的范围增强和聚爆，不含遗物 / 法杖。实体上的真实爆炸圈则含遗物 / 法杖。遗物把圈撑大，聚爆仍按 ×50% 缩小，但转伤少算了遗物 / 法杖多出来的米。
转伤还要求表 radius > 0 或有坠落附加圈。魔法弹 radius=0 且没挂坠落时，整句不进。

4.4 表 radius=0

魔法弹等配置半径是 0。Calculate() = FallRadius × (1+AddRatio) × MulRatio。

  • 没挂坠落：数值半径仍是 0。自动填槽不会配这张卡。
  • 手动插上：硬编码圈、召唤探测 / 自爆，以及「把 Scale 设成 Calculate()」的法术，仍按 1+AddRatio 放大。弹体预制碰撞盒不会只因为这张卡变大。
  • 只挂范围增强、不挂坠落：悬停第二段也读 Calculate()，圈仍是 0。

4.5 召唤

配置写了不对召唤生效，运行时不读。手动插在召唤左侧，撞击 / 自爆 / 虚空炸 / 探测距离按各召唤自己的基数 × 半径比。体型缩放有的加虚胖的 ExtraSizeRatio，有的乘范围增强的 extraSizeRatio，不要混。

4.6 虚胖不是范围增强

虚胖走 GetSpellVolumeRatio → SpellNeedResize.ExtraSizeRatio。SpellResizeSystem 只在 ResizeByDamage 时把它叠到 Scale。范围增强从不写这个字段。两张可以同时在：一张改命中/爆炸半径，一张改体积。

4.7 公转 / 自由公转

AroundRadius 只来自公转 / 自由公转自己的 float3，烘焙时不乘 extraSizeRatio。AI 距离估算会把公转半径再乘 CurrentFinalRatio，那是估算不是实体环绕半径。破法者一类用半径比做随机偏移，属于该法术自己的读法。

4.8 自动填槽

  1. Filter_EffectRangeEnhance：主法术必须 radius > 0。
  2. SpellAvoidEnhances：陨石、诡雷、阿瓦达啃大瓜避开范围增强（也避开自我追踪）。
  3. Filter_SummonOnlyEnhance：因为 haveEffecforMissileSpell=true，不会被滤成只给召唤。

避开只约束自动填。手动插在这三张左侧，爆炸圈 / 地面圈仍吃加算。Lv1 表半径：陨石 1.2、诡雷 1.5、阿瓦达 0.8。

4.9 卡面半径和实伤圈

提示框对龙息、超新星不显示半径。其它法术在 radius != 0 或有坠落附加圈时显示。坠落那一项加了遗物、没再加法杖；实体 Calculate() 则是 (Base+Fall) 一起乘「增强+遗物+法杖」。有坠落 + 全杖半径% 时，卡面可能比实圈略小。以实体为准。

6. Mono 残留轨对照

SpellBase 用 radiusRatio += extraSizeRatio、finalRadiusRatio *= finalSizeRatio，再 spellCfg.radius *= radiusRatio * finalRadiusRatio。和 ECS 的 (1+AddRatio)*MulRatio 是同一层。

和 ECS 的差别在分裂：

ECS ToSplitMono CreateSplitSpellInitialParameter
表半径Base *= 0.8finalSizeRatio *= 0.8
坠落附加圈不缩跟着 finalRadiusRatio 一起 ×0.8
伤害系数×0.33（写死）×0.35

玩家主路径以 ECS 为准。

8. 待决 / 局限

  1. 遗物/诅咒逐条：只确认三类来源（远程射击、加半径遗物、减半径诅咒），不逐条展开。
  2. 各法术 Job 额外改半径：充能泡、闪亮星矢层数等是该法术自己的层，不在此穷尽。
  3. 魔法弹命中盒：未逐预制体核对；结论停在「Calculate() 为 0 时，这张卡不会凭空变出爆炸圈」。
  4. 公转实体半径：烘焙不乘；若日后有通用 Job 改成乘 AddRatio，需要重验 4.7。
