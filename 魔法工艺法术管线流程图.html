槽位解析：SlotData[] → SpellShootGroup[]

这是整个系统最核心的算法：法杖格子里的一排符文，如何被"编译"成若干个发射组。只在槽位变更时执行一次（装杖 / 拾取 / 合成 / 重置），不是每帧或每次开火重算。

阶段 A = 扁平化扫描（构造函数）；阶段 B = 分组与子组递归（NextGroup / NextShoot）。

解析产物结构

shootGroups : List<SpellShootGroup> └─ Shoots : List<SpellShootData> ← 同一组内 = 同时发射（Volley 提升上限） ├─ Spell : SlotData ← 可发射法术（Missile / Summon） ├─ EnhanceList : SlotData[] ← 该法术左侧累积的强化符文 ├─ Triggers : SlotData[] ← 紧跟其后的触发器符文 └─ SubGroup : SpellShootGroup ← 触发器要发射的内容（递归结构，可嵌套）

帧内 System 执行时序

还原自各 System 的 [UpdateInGroup] / [UpdateBefore] / [UpdateAfter] / OrderFirst / OrderLast 特性。点击 System 查看职责。

注意：FixedStepSimulationSystemGroup 嵌套在 SimulationSystemGroup 内，每帧可能执行 0～N 次（定步长追帧），因此"移动 + 碰撞"的频率与渲染帧率解耦。

触发器（扳机）与派生法术

触发器符文本身不产生效果，而是把"它右侧的一段法术"打包成 SubGroup，在满足条件时再走一遍完整发射管线。

五种触发器

统一触发发射链路

触发条件满足 → ShootSpellBuffer.ShootByTrigger(shooterEntity, shooterData, subGroup, spatial, builder) → ApplyShooterEntity + ApplyWandEffect ← 继承施法者/法杖上下文 → ShootSpellUtils.ShootSpellGroup(subGroup, ...) ← 与玩家开火共用同一入口 → CreateShootInfoFromShootGroup → SipToSSP → SpellShootSystem.Shoot

派生法术：分裂 / 反弹 / 折射

数值计算链

法术的所有可叠加数值都走统一容器，区分"加算"与"乘算"两条通道，这是搭配深度的数学基础。

通用数值容器（托管层 RatioValue / ECS 层 AttributeValue）

// RatioValue.cs:36 —— 托管层（UI 预览、法杖计算） Result = (BaseValue + addBase) × baseAddRatio × addRatio × mulRatio + addExtra // AttributeValue.Calculate() —— ECS 层（实际战斗结算） Result = (Base + AddBase) × (1 + AddRatio) × MulRatio + Extra // addRatio ← 多来源【相加】 mulRatio ← 多来源【相乘】

伤害链：强化符文 → 玩家 → 法杖

最终伤害 = 法术基础 damage × ( 1 + Σ加算[EnhanceAttackRatio.float1 / FireCrystal.float1 / OverDrive.float1] + PlayerMgr.ExtraDamageRatio ) × Π乘算[Refraction.float2 / PowerSavingMode.float3] × wand.passiveDamageRatio ← 遗物/法杖被动 × WandCfg.damageCorrection / 100 ← 法杖自身伤害修正 // 关键：只统计【同一段插槽序列中、目标法术之前】的 Enhance // → 这就是"强化符文必须摆在主动法术左侧"的代码依据 (CanShootSpellUtils.GetDamage 的 stopTarget 提前 return) // DPS 类法术：info.damage = Damage.Calculate() × DamageInterval

蓝耗链：组内 → 法杖 → 电池池

单发 mpCost = SpellConfig.mpCost × OwnerGroup.GetGroupManaCostRatio() ├─ Volley : pow(float1 / 100, n − 1) ← 齐射数越多单发越便宜/贵 ├─ Multishot : Π mpCostMulDivCorrection └─ ArcaneNova / PreFirework 父法术比例修正 × summonTypeSpellManaCostRatio ← 召唤类 + LowerSummonManaCost 法杖 × 父组 shootCount / SubGroup 触发次数 × Enhance 的 mpCostMulDivCorrection ← Split / PowerSaving / OverDrive × wand.GetWandMpCorrection() ├─ WandCfg.costCorrection ├─ passiveMpCostCorrection ← ChargeMode 等 └─ PlayerMgr.MpCostRatioFromWandAbility() 组 mpCost = Σ 各 SpellShootData（+ SubGroup，若 NeedCostSubGroupMana） 扣费顺序 : 本杖 CurrentMP → 不足部分从 Battery 法杖池扣 (CostMpFromWandAbility) 蓄能槽 : PostSlotMaxCharge = Σ 各 post 组 mpCost，充能满即发射，不再扣 MP
