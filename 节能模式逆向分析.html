节能模式（Spell3104 / PowerSavingMode）逆向分析

范围：仅玩家强化符文「节能模式」（abilityType = 3104，配置 ID 31041–31043）。重点是三轴乘算怎么进快照，以及哪些字段是死的。

不展开遗物/诅咒逐条来源，也不穷尽每个 abilityType 的 Job。

方法：SpellConfig.json + 反编译 Assembly-CSharp 交叉验证。未标注「推测」的结论均有代码/数据直接证据。

玩家施法主路径是 ECS。Mono SpellBase.ApplyEnhanceSpell 会多砍召唤 HP，文末单独对照。

配套：总览见《魔法工艺法术系统逆向报告.md》，原始数值见《法术数值总表.md》，加算/乘算容器见《伤害强化逆向分析.md》，持续与悬停分家见《悬停逆向分析.md》，子弹继承伤/持续见《分裂逆向分析.md》。

文案（TextConfig_Spell id 7131041–7131043）只写两段：

法术持续时间 ×float2%

卡面数值行还会额外打出 mpCostMulDivCorrection（该字段非 0 时追加「耗蓝 ×N%」）。float1、int1 不出现在文案里。

2. 数值与字段语义

2.1 配置表（assets_export/SpellConfig.json）

3104117575×60%703011true

规律：售价每级 ×3。Lv1 与 Lv2 的伤 / 持续完全相同，Lv2 只多省蓝。Lv3 伤 / 持续惩罚变轻（75%→80%），耗蓝再降到 ×40%。

2.2 字段语义

字段语义运行时是否被读置信度
float3伤害乘算百分比；MulRatio(float3 / 100)是高
float2持续乘算百分比；MulRatio(float2 / 100)是高
mpCostMulDivCorrection耗蓝乘算百分比；与多重 / 分裂 / 过载同开关是（发射扣蓝时）高
float1配置 70 / 50 / 30ECS / Mono 均未读高
int1配置 30 / 45 / 70ECS / Mono 均未读高
int2 / int3配置为 0未读高
haveEffecforMissile/Summon对弹幕与召唤都标为生效；三个入口不读这两个字段过滤只出现在自动填槽高

PowerSavingMode 在整个 Assembly-CSharp 里只有四处 case：GetDamage、GetSpellDuration、GetSpellManaCost、SpellBase.ApplyEnhanceSpell。四处都只碰 float3 / float2 / mpCostMulDivCorrection，没有一处读 float1 或 int1。

没有 Spell3104*System / Authoring。它不是行为组件，只是被三个 getter 读 abilityType 后改比率。

2.3 等级没有线性等价

伤害强化是加算，1×Lv2 = 2×Lv1。节能是连乘，而且等级改的不是同一组数：

组合伤害 / 持续耗蓝
1×Lv1×0.75×0.60
1×Lv2×0.75（与 Lv1 相同）×0.50
1×Lv3×0.80×0.40
2×Lv1×0.5625×0.36
Lv1+Lv2×0.5625×0.30

合成 Lv1→Lv2：伤 / 持续不变，只把耗蓝从 ×60% 换成 ×50%，并省 1 格。合成 Lv2→Lv3：伤 / 持续惩罚变轻，耗蓝再降。两张低级卡连乘会把伤 / 持续打得比一张 Lv3 狠得多。

3. 三轴怎么叠（核心）

三轴都是 MulRatio，内部 mulRatio *= val，初值 1。同 abilityType 出现几次乘几次。无上限、无「只取最高级」。

3.1 伤害：加算之后再乘

case EnhanceAttackRatio / FireCrystal / OverDrive:
    ratioValue.AddRatio(enhance.float1 / 100f);
case Refraction:
    ratioValue.MulRatio(enhance.float2 / 100f);
case PowerSavingMode:
    ratioValue.MulRatio(enhance.float3 / 100f);

RatioValue.ResultDouble = (Base + addBase) * baseAddRatio * addRatio * mulRatio + addExtra。

最终伤害 ≈ B × (1 + Σ加算%) × Π(折射 float2/100) × Π(节能 float3/100)

伤害强化 / 炽焰 / 过载先加总，节能和折射再连乘。法杖 passiveDamageRatio、damageCorrection/100 再乘一层。详见《伤害强化逆向分析.md》第 5 节。

烘焙：sip.finalDamageRatio *= CurrentMulRatio → Damage.MulRatio。实体：(Base + AddBase) * (1 + AddRatio) * MulRatio + Extra。

3.2 持续：乘 (Base + AddBase)，不乘 Extra

case EnhanceDurationValue:     AddBase(float1);      // 时长强化
case PowerSavingMode:          MulRatio(float2/100); // 节能
case RandomRotationRadiu:      AddBase(float3);      // 自由公转
case AroundMouse:              AddBase(float2);      // 寻踪

GetSpellDuration_FinalPlayerValue 原样返回，没有玩家额外层。

实体持续 = (表 duration + AddBase) × Π(节能 float2/100) + Extra

Extra 在 MulRatio 之后相加，公转 3009 自己那截额外持续不被节能打折。主观缓时换来的秒写进 extraDuration（AddBase），要乘。

表 duration = 0 且没有 AddBase 时，乘完仍是 0。文案「持续时间 ×75%」只对「已经有持续」的法术有可见效果。

3.3 耗蓝：与多重 / 分裂 / 过载同开关

case Multishot / SpellSplit / PowerSavingMode / OverDrive:
    ratioValue.MulRatio(mpCostMulDivCorrection / 100f);

GetSpellManaCost_FinalPlayerValue 再乘 wand.GetWandMpCorrection()（杖表、杖被动、全杖能力、耗蓝诅咒）。

耗蓝修正只在母弹发射扣蓝时用过，不写入 SpellSpawnParams。分裂子弹、回响再放都不重扣这一层。

3.4 常见误解

误解实际
两张 Lv1 伤变成 ×0.75+0.75连乘成 ×0.5625
Lv2 比 Lv1 伤更低伤 / 持续相同，只是更省蓝
持续也会打折悬停第二段悬停走 HoverDuration，不进 GetSpellDuration
耗蓝打折会进快照、子弹再扣一次只在开火扣蓝用
float1 / int1 是隐藏的速度或冷却配置非零，运行时无引用
召唤血量也按 float3 打折ECS GetSummonHp 没有该分支

4. 谁吃得到这张卡

4.1 只强化自己右边、同一段

SpellGroupParser 从左到右把 Enhance 推进 list2，遇到主动法术后也不清空。主槽 / 后槽分段 Parse，互不加。

节能弹球 → 两张都吃三轴
弹节能球 → 只有球吃
弹球节能 → 都吃不到
A弹B球 → 弹吃 A；球吃 A×B

主槽最左的一张会强化本段之后所有主动/召唤（含同一段里触发器后的后槽法术）。主槽加不到 postSlots。

4.2 stopTarget 对主动法术不截断

主动法术 GetSpellDamage() 的 stopTarget 是自己，不在 EnhanceList 里，列表里每张节能都会乘上。

闪电链 / 生命线以「强化自己」为基数：循环扫到那张链/线就 return，因此只有它左侧的节能计入该张链伤 / 生命线伤。

4.3 魔能升阶抬的是这张卡的等级

GetFinalConfig()。升阶把 31041 抬成 31042 / 31043。Lv1→Lv2 抬完伤 / 持续仍是 75%，只有耗蓝从 60 变成 50。

4.4 自动填槽

SpellAutoFullTool 没有针对 3104 的专用滤网。haveEffecforMissileSpell=true，不会被滤成「只给召唤」。避让表也不避开节能。

5. 谁真正读到这三轴

5.1 伤害

谁读 Damage.Calculate()，谁就吃 float3。包括弹幕直伤、召唤体攻击、闪电链、生命线。链 / 线以自身为 stopTarget，只吃自己左边的节能。

5.2 持续

机制吃不吃怎么吃
弹幕寿命（DurationTimer >= Calculate()）吃表持续 + AddBase 后乘 MulRatio
时长强化 3103吃AddBase 先加秒，再被节能乘
寻踪 3010 的 float2吃GetSpellDuration AddBase
自由公转 3117 的 float3吃同上
主观缓时 3128 换来的秒吃写入 extraDuration 之后乘
公转 3009 的 float1不吃进 Duration.Extra，加在乘之后
悬停 3008不吃只加悬停自己的 float1，不进 Duration
冷却 / 射击间隔不吃不改 WandCoolDown / shootInterval
飞行速度不吃不进 GetSpellFlySpeed
半途传送间接吃半程点按 Calculate()/2
龙息耗蓝双吃见 5.3
部分召唤寿命吃(基数 + AddBase) × MulRatio

5.3 耗蓝

机制吃不吃怎么吃
主动 / 召唤开火扣蓝吃GetSpellManaCost 连乘
多重 / 分裂 / 过载的耗蓝修正同层连乘同一 switch
法杖 / 诅咒耗蓝修正再乘一层GetWandMpCorrection
后槽整组看 EnhanceList同段左侧会挂上；组倍率那层只再乘多重
分裂子弹 / 回响再放不重扣修正不进快照
奥术屏障抵伤不吃30 蓝/血不变
低耗高伤法杖间接吃实扣蓝压到杖 int1 以下时再加算；这笔加算仍被伤害 MulRatio 乘一次
龙息 1025双吃BaseValue = float2 × GetSpellDuration()（持续已被乘过），耗蓝 ×60%/50%/40% 还在

5.4 召唤 HP：ECS 不砍

GetSummonHp 只认巨魔血清和尸爆/献祭，没有 PowerSavingMode。玩家主路径召唤血量不按 float3 打折。Mono 残留会砍，见第 7 节。

5.5 分裂：伤 / 持续已烘焙，耗蓝不重扣

ToSplit 整包复制快照。节能的伤害 / 持续 MulRatio 已经在母弹发射时写进去，子弹带着走，再额外 ×0.33 伤、×0.8 半径、×0.5 速度（非坠落）。耗蓝修正不会再跑一遍。

6. 和其它法术的关系

7. Mono 残留轨对照

玩家主路径 shootFromSpellGroupV2 = true，走 SIP 烘焙。V2 的 switch 没有 PowerSavingMode，三轴都以 SIP 为准。

旧路径 ApplyEnhanceSpell：

case PowerSavingMode:
    damageRatio *= float3 / 100f;
    SpellSUmmonFinalHpRatio *= float3 / 100f;
项ECS / SIP（玩家主路径）Mono ApplyEnhanceSpell
伤害GetDamage → Damage.MulRatiodamageRatio *= float3/100
持续GetSpellDuration → Duration.MulRatio此 case 不改
耗蓝GetSpellManaCost此 case 不改
召唤 HPGetSummonHp 不乘节能SpellSUmmonFinalHpRatio *= float3/100

讨论玩家构筑时以 ECS 表为准：召唤血量不被节能砍。

9. 待决 / 局限

  1. float1 / int1 的设计意图：配置随等级单调变（70→50→30，30→45→70），很像旧版速度 / 冷却 / 省蓝百分比，但当前二进制无引用。标「未读」，不猜旧语义。
  2. 各法术 Job 手写寿命：充能泡、闪亮星矢、鱼叉等可能在 Calculate() 之外再改计时，不在此穷尽。
  3. 召唤寿命：确认部分路径读 Duration.MulRatio；未逐个召唤 prefab 核对是否另有写死秒数。
  4. 遗物 / 诅咒耗蓝：只确认走 GetWandMpCorrection 再乘一层，不逐条展开。
